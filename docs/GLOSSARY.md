# LegalMind Glossary & Terminology Index

This document establishes the canonical terminology for the LegalMind backend, databases, retrieval pipelines, and conversational components. All project documentation, code comments, and technical specifications must adhere strictly to these definitions.

---

## Terminology Matrix

| Term | Domain | Definition & Technical Context | Implementation Reference |
|---|---|---|---|
| **User Query** | Conversation | The raw text input submitted by the user in a chat turn. May contain conversational phrasing, pronouns, or implicit context from earlier turns. | `req.body.message` in `src/modules/conversations/conversation.controller.ts` |
| **Original Query** | Pipeline | The exact raw user input prior to any classification, rewrite, or normalization step. | `originalQuery` in `QueryRequest` DTO |
| **Standalone Retrieval Query** | Memory / Pipeline | A self-contained, disambiguated search query generated by `ConversationMemoryService` using recent conversation history to resolve pronouns, ellipsis, and context shifts. | `resolvedQuery` returned by `ConversationMemoryService.resolveQuery()` |
| **Classification** | Pipeline | The process performed by `ClassifierService` categorizing a query into one of three intent branches: `social_chat`, `exact_reference`, or `legal_question`. | `ClassifierService.classify()` |
| **Legal Reference** | Utility / Parsing | An explicit structural citation extracted by `legal-ref-parser.ts` targeting specific legislation (law number, law year, article number) or court rulings (appeal number, judicial year). | `ParsedLegalRef` returned by `parseLegalRef()` |
| **Exact Lookup** | Retrieval | A deterministic database query executed by `LegalRefService` attempting to fetch exact legal article or court ruling chunks without vector search overhead. | `LegalRefService.lookupExactRef()` |
| **Hybrid Retrieval** | Retrieval | Search execution by `RetrievalService` combining MongoDB Atlas Vector Search (dense embeddings) and Atlas Text Search (lexical tokens) via Reciprocal Rank Fusion (RRF). | `RetrievalService.retrieve()` |
| **Vector Search** | Search | Cosine similarity matching between query embedding vectors and stored 1024-dimensional legal chunk vectors using MongoDB Atlas Vector Search (`legal_chunks_vector`). | `$vectorSearch` pipeline in `RetrievalService` |
| **Text Search** | Search | Keyword and token-matching search over normalized Arabic legal text using MongoDB Atlas Search (`legal_chunks_text`). | `$search` pipeline in `RetrievalService` |
| **Reranking** | Retrieval | Re-scoring candidate chunks using Qwen LLM reranker (`qwen3-rerank`) or a fallback structural heuristic to order candidate chunks by semantic relevance. | `RerankerService.rerank()` |
| **Grounding** | RAG Policy | Validation enforced by `grounding-policy.ts` ensuring retrieved evidence meets minimum relevance score thresholds (`MIN_QUALIFIED_SCORE = 0.40`) before LLM generation. | `evaluateGrounding()` in `grounding-policy.ts` |
| **Qualified Evidence** | Grounding | Retrieved legal chunks that satisfy jurisdiction, governance, and relevance score thresholds, making them eligible for inclusion in the prompt context. | `qualifiedEvidence` in `GroundingResult` |
| **Source Snapshot** | Persistence | An immutable historical copy of source metadata (title, article number, excerpt, law number, year) attached to an assistant message to freeze legal citations at query time. | `SourceSnapshotService.createSnapshots()` |
| **Assistant Message** | Conversation | A persisted response turn generated by LegalMind, containing generated text, source snapshots, retrieval diagnostics, and error metadata. | `IMessage` in `src/modules/conversations/message.model.ts` |
| **Conversation** | Conversation | A stateful user session containing a sequence of user and assistant messages, thread metadata, summary, and ownership scoping. | `IConversation` in `src/modules/conversations/conversation.model.ts` |
| **Corpus Release** | Governance | A tracked release version of the Egyptian legal text dataset, representing a validated snapshot of laws, decrees, and court rulings. | Scripted governance in `src/scripts/audit-legal-corpus.ts` |
| **Authority** | Governance | A primary legal instrument (e.g., Constitution, Law No. 12 of 2003, Court of Cassation Ruling) containing legal articles or paragraphs. | `authorityId`, `authorityTitle`, `authorityType` on `LegalChunk` |
| **Legal Chunk** | Data Model | The fundamental unit of retrieval in LegalMind—a indexed segment of legal text representing an article or paragraph with embeddings and metadata. | `LegalChunk` in `src/models/chunk.model.ts` |
| **Application Database** | Storage | The `legalmind_app` MongoDB database storing user accounts, refresh tokens, active conversations, messages, and security audit events. | Connected via `MongoService.appConn` |
| **RAG Database** | Storage | The `legalmind_rag` MongoDB database storing the indexed legal corpus (`legal_chunks`), vector search indexes, and legal governance registries. | Connected via `MongoService.ragConn` |

---

## Usage Rules

1. **System Documentation**: All markdown files in `docs/` must use the exact capitalization and spelling defined in the matrix above.
2. **Code Comments**: Variable names and TypeScript docstrings should align with these terms (e.g., use `standaloneQuery` rather than `rewrittenHistoryQuery`).
3. **API Contracts**: External DTO fields should reflect these canonical terms (e.g., `qualifiedEvidence`, `sourceSnapshots`).
